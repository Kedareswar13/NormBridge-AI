# NormBridge AI

**Your university policy assistant: it connects natural-language questions to official rules and page-level evidence.**

Self-hosted RAG over SRM University-AP policies, with OCR for scanned PDFs and built-in deterministic evals.

Flask · React · PostgreSQL · ChromaDB · Ollama (Qwen2.5 / nomic-embed-text / GLM-OCR) · Hybrid retrieval (vector + BM25) · Cross-encoder re-ranking

## What it does

Students and staff ask questions in plain English ("What is the minimum attendance to write the end-sem exam?") and get an answer **grounded in the official policy PDF**, with the source pages shown as evidence. Everything runs locally and free: no paid APIs, no data leaves the machine.

- **20 official SRM AP policies** (attendance, hostel, refunds, anti-ragging, code of conduct, plagiarism, PhD and more) fetched from srmap.edu.in into `data/policies/`.
- **OCR for scanned PDFs**: the PDF text layer is used where it exists; scanned pages go through **GLM-OCR** (via Ollama on Windows/Linux, or MLX on Apple Silicon), with Tesseract, EasyOCR and RapidOCR as fallbacks. Results are cached in `data/ocr_cache/`, so OCR runs once per document.
- **Indexing**:
  - **structure-aware chunking**: clauses and lists stay together across pages, and table rows keep their header row;
  - **contextual chunk headers**: "document title > section" is embedded with every chunk, which separates near-duplicate policies such as Student vs Employee grievance.
- **Retrieval pipeline**:
  1. query validation;
  2. **follow-up rewriting** for multi-turn chats (with a drift guard);
  3. role-scoped semantic answer cache;
  4. **hybrid retrieval**: vector search (ChromaDB, 768-d `nomic-embed-text`) + a BM25 keyword index, both filtered by role and tenant, **fused with Reciprocal Rank Fusion**;
  5. best-document selection with **cross-encoder doc-level re-ranking**, plus **multi-document answers** when a second policy is nearly as relevant;
  6. chunk re-ranking;
  7. **contextual compression** (the top chunk keeps up to 220 words, the others 70);
  8. answer generation in a fixed prompt template. **Query routing**: yes/no questions go to a bigger model (`qwen2.5:3b` locally, `llama-3.3-70b` in the cloud), because small models have a measured "yes" bias;
  9. guardrails and evals.
- **Streaming**: answers stream token by token over Server-Sent Events (`POST /chat/stream`), and the "thinking" panel shows the real pipeline stage.
- **Chat history that survives**: conversations are stored server-side per user (owner-only, signed-token identity). Logout/login, refresh, cleared browser storage or another device all show the same history.
- **Tracing**: every request records spans (rewrite, embed, cache, retrieve, rerank, LLM with time-to-first-token, evaluate) with no question text. They're shown as a waterfall with p50/p95 per stage in Admin → Traces, with optional OpenTelemetry export (`OTEL_EXPORTER_OTLP_ENDPOINT`).
- **Fast on a CPU laptop**:
  - **~5–6 s average answer** with `qwen2.5:1.5b` (follow-ups add ~2 s for the rewrite), and **~0.4 s** for repeated or paraphrased questions.
  - Five cache layers: embedding LRU, cross-encoder score LRU, role-partitioned semantic answer cache, Ollama KV-prefix reuse (constant system prompt), and models kept warm.
  - Per-stage timings are returned with every answer.
  - Caches are invalidated automatically when policies change.
- **RAG security in four layers, on top of signed identity**:
  - **Identity:** the user's identity comes from a **server-signed, expiring session token** issued at login, never from an email the browser sends.
  1. **query validation** (prompt injection, exfiltration, role hijack) before retrieval;
  2. **role and tenant access control** inside the vector and keyword search (staff-only documents never reach students);
  3. a **fixed prompt template** with sanitised data slots;
  4. a **PII-masked audit log** (pseudonymous user id, masked query, document/chunk ids only), shown in Admin → Security.
- **Evals (deterministic, zero cost, plus an optional LLM judge)**:
  - **Live**: every answer is scored for groundedness, numeric faithfulness, context relevance and abstention.
  - **Golden set**: 54 curated questions with verified answers. They include:
    - out-of-scope questions that must be refused;
    - prompt-injection attacks that must be blocked;
    - access-control cases;
    - **multi-turn follow-ups**;
    - **yes/no verdict checks** (the right words with the wrong Yes/No fail).
    
    Run it with one click in Admin → Evaluation, or `scripts/run_evals.py` (CI-style quality gate).
  - **Held-out set**: 20 questions generated by a different model, with **verbatim** answer spans, never used for tuning (`scripts/make_heldout_set.py`, `run_evals.py --set heldout`). It checks that improvements generalise beyond the hand-written set.
  - **LLM-as-judge**: `scripts/judge_run.py` grades a run with a bigger local model and reports its **agreement (Cohen's kappa)** with the deterministic scorer.
  - **Eval-driven fixes, shown not told**: Admin → Evals & Quality opens with a pass-rate **timeline** annotated with what changed before each run, a **case × run heatmap** (when each problem was caught and which run fixed it), and **Compare two runs** with both answers side by side (e.g. #3 → #16: 12 fixed, 1 regression caught). The same story, with real quoted answers, is in [docs/EVAL_FINDINGS.md](docs/EVAL_FINDINGS.md) (generated from the eval database by `scripts/eval_findings.py`, which checks every claim against the stored results).
- **CI**: GitHub Actions runs the unit tests and the UI production build on every push.
- **Admin console**: upload (with audience), version and compare policies; see users and chat history; analytics, evals, security and traces dashboards; cache stats.
- **Professional, animated UI**:
  - a full-screen dark theme (light theme one click away) and a ChatGPT-style centred chat lane;
  - a floating composer with voice input and a model picker;
  - a live **"thinking" panel** while the answer is generated;
  - answers that **type out character by character** (click to skip);
  - a **grounding badge** and response time on every answer;
  - copy, sources, read-aloud and feedback actions;
  - responsive, with reduced-motion support.
- **Voice input** in the chat via the browser Web Speech API.
- **Deploy for free**: Vercel UI + Hugging Face Space API + Neon Postgres + Groq free LLM, in a step-by-step guide: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Quick start (Windows, no admin rights needed)

```powershell
# 1. one-time setup: .env, portable PostgreSQL, Python venv, Ollama models, npm packages
powershell -ExecutionPolicy Bypass -File .\setup.ps1

# 2. start everything (Postgres, Ollama, API on :5001, UI on :3000) and ingest the policies on first run
powershell -ExecutionPolicy Bypass -File .\run.ps1 -Ingest

# 3. stop
powershell -ExecutionPolicy Bypass -File .\run.ps1 -Stop
```

- Chat: http://localhost:3000. Use any `@srmap.edu.in` email; the domain is configurable via `ALLOWED_EMAIL_DOMAIN`.
- Admin: http://localhost:3000/admin, using `ADMIN_USERNAME` / `ADMIN_PASSWORD` from `.env`.

Moving to another laptop: see [docs/PERSONAL_LAPTOP_SETUP.md](docs/PERSONAL_LAPTOP_SETUP.md).

## Project layout

```

  services/ocr_service.py     text-layer + GLM-OCR extraction with cache
  services/rag_service.py     embeddings, caches, hybrid search (vector + BM25), re-ranking, compression
  services/chunking.py        structure-aware chunking (tables keep headers) + contextual chunk headers
  services/retrieval_utils.py Reciprocal Rank Fusion
  services/query_service.py   follow-up (multi-turn) query rewriting with a drift guard, yes/no detection for routing
  services/llm_service.py     answer generation (optionally streamed): local Ollama or any OpenAI-compatible API
  services/prompt_service.py  fixed prompt template with sanitised slots (security layer 3)
  services/security_service.py  query validation, roles/tenant filters, PII masking, audit log (layers 1, 2, 4)
  services/conversation_service.py  per-user chat history (server-side, owner-only)
  services/tracing.py         per-request spans (Admin -> Traces), optional OpenTelemetry export
  core/session.py             signed, expiring session tokens (who is asking)
  services/eval_service.py    deterministic evals (live + golden + held-out sets)
  routes/chat.py              the RAG pipeline end to end: /chat (JSON) and /chat/stream (SSE), /conversations
frontend/           React app (ChatApp, Admin, components/EvalsPanel + SecurityPanel + TracesPanel, streamChat.js, styles/)
data/policies/      official policy PDFs + manifest.json (source URL, sha256, category)
data/ocr_cache/     cached extraction per PDF hash (portable)
evals/              golden_set.json, heldout_set.json + generated reports
data/db_snapshot/   database snapshot for the portable zip (git-ignored; restored by setup.ps1)
guides/             CareHarbor AI build brief, free AI-coding setup
scripts/            fetch_policies, ocr_prefetch, ingest_policies, run_evals, judge_run, eval_findings, make_heldout_set, make_portable_zip, prepare_hf_space
deploy/hf-space/    Dockerfile + start script for a free Hugging Face Space
tests/              unit tests: evaluator, security, chunking, RRF, rewriting, routing, tokens, history, tracing
.github/workflows/  CI: unit tests + UI build
docs/               setup guide, deployment, gap analysis, eval findings, project review, RAG concepts map, learning roadmap
```

## Useful commands

```powershell
python scripts\fetch_policies.py                                   # (re)download official PDFs
backend\.venv\Scripts\python scripts\ocr_prefetch.py               # OCR scanned PDFs once, fill data\ocr_cache
backend\.venv\Scripts\python scripts\ingest_policies.py            # upload data\policies to the API
backend\.venv\Scripts\python scripts\run_evals.py --min-pass-rate 0.8   # golden-set evals + markdown report
backend\.venv\Scripts\python scripts\run_evals.py --set heldout    # held-out set (never used for tuning)
backend\.venv\Scripts\python scripts\judge_run.py                  # LLM-as-judge on the latest run + agreement (kappa)
backend\.venv\Scripts\python scripts\run_evals.py --note "what changed"   # annotate the run on the Admin timeline
backend\.venv\Scripts\python scripts\eval_findings.py              # regenerate docs\EVAL_FINDINGS.md from the eval database
backend\.venv\Scripts\python -m pytest tests -q                    # unit tests (46)
powershell -File scripts\make_portable_zip.ps1                     # zip for another machine (incl. database snapshot)
```

## Configuration

All settings live in `.env`; see [.env.example](.env.example). Key ones:

- `OLLAMA_MODEL` (default `qwen2.5:1.5b`; `qwen2.5:3b` and `phi3:mini` are selectable in the chat), `EMBEDDING_MODEL`, `OLLAMA_OCR_MODEL`
- `DB_*` or `DATABASE_URL`
- `ADMIN_USERNAME`, `ADMIN_PASSWORD`
- `ALLOWED_EMAIL_DOMAIN`, `STAFF_EMAILS` / `STAFF_EMAIL_REGEX` (who counts as staff), `TENANT_ID`, `AUDIT_SALT`
- `SESSION_SECRET` (signs login tokens; generated by `setup.ps1`), `SESSION_TTL_HOURS`
- Speed:
  - `CPU_THREADS`, `MODEL_KEEP_ALIVE`, `LLM_MAX_TOKENS`;
  - `RERANK_TOP_K`, `PROMPT_TOP_CHUNK_WORDS`, `PROMPT_CHUNK_WORDS`, `SEMANTIC_CACHE_THRESHOLD`.
- Quality:
  - `YESNO_MODEL` / `YESNO_API_MODEL` (yes/no routing);
  - `MULTI_DOC_MARGIN` (second-document answers, 0 = off);
  - `CHUNK_WORDS` (re-ingest with `ingest_policies.py --force` after changing it).
- Observability: `TRACE_RETENTION`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SERVICE_NAME` (OTel export needs `pip install opentelemetry-sdk opentelemetry-exporter-otlp`).
- `OCR_DPI`, `LLM_TIMEOUT`, `RERANK_PDF_CANDIDATES`
- `LLM_PROVIDER`, `LLM_API_BASE`, `LLM_API_KEY`, `LLM_API_MODEL`: use a free hosted LLM instead of Ollama (see DEPLOYMENT).
